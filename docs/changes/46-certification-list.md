## 판단한 내용

- **한 항목에 보이는 것:**
  - 자격증명(`h2`)과 만료됐으면 "만료됨" 배지
  - "발급 기관 · 점수·등급"(점수가 없으면 발급 기관만)
  - "취득 YYYY-MM-DD · 만료 YYYY-MM-DD"
  - 입력한 경우 메모
- **만료 없음:** 만료일이 `null`이면 날짜 대신 "만료 없음"으로 씁니다(완료 기준).
- **만료 표시(#35에서 화면으로 넘긴 결정):** 만료일이 오늘보다 앞이면 "만료됨" 배지를 붙입니다.
  - 만료일 당일까지는 유효로 봅니다.
  - 만료된 자격증도 이력이라 목록에서 빼거나 흐리게 하지 않습니다.
  - 배지는 색이 아니라 글자로 구분합니다(`outline`).
- **오늘은 서비스 시간대(Asia/Seoul) 기준입니다.** 서버의 `serviceDate`와 같은 방식(`Intl.DateTimeFormat`에 `Asia/Seoul` 지정)으로 계산합니다. 기기 시간대가 달라도 한국 날짜가 바뀌는 자정에 만료 표시가 바뀝니다. 테스트는 UTC로는 아직 전날인 한국 시간 00:30으로 확인합니다.
- **순서:** API 순서(취득일 최신순, 같은 날은 나중 등록이 위)를 그대로 씁니다.

## 1차 리뷰 반영

결함은 없었습니다. 리뷰에서 확인한 것은 아래와 같습니다.

- 서비스 날짜 계산이 서버 `serviceDate`와 같습니다.
- 만료일 당일은 유효로 봅니다.
- 테스트는 `TZ=UTC`로 돕니다. 그래서 `serviceToday`가 기기 날짜나 UTC 날짜를 쓰면 시간대 테스트가 실패합니다.
- 가짜 타이머가 `Date`만 바꿔서 결과가 오락가락하지 않습니다. 4회 실행해 모두 통과했습니다.
- 접근성 구조가 이력 목록과 같습니다.
- 배지와 "메모" 글자가 14px입니다.

낮음 1건을 반영했습니다. 테스트 파일의 `afterEach(() => vi.useRealTimers())`는 `src/test/setup.ts`가 이미 하는 일이라 지우고, 주석에 그 사실을 적었습니다.

- 반영 후 정적 검사(포맷·lint·타입)와 프론트엔드 테스트 175건 통과·2건 건너뜀. 백엔드는 바뀌지 않았습니다.
