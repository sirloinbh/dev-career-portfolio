# Hiring stages and a status history for applications (#229)

An application moves through eight hiring stages and every change of stage is saved with its date. User decision 2026-11-27: drafting, submitted, document passed, first interview, second interview, offer, rejected, withdrawn; old `closed` rows become `rejected`.

| File                                                                        | Change                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `database/migrations/013_application_stages.sql`                            | Replaces the status check with the eight stages, maps `closed` to `rejected`, creates `application_status_history` (cascade delete) and gives every existing application one row dated with its last edit (earlier change dates were never recorded). Safe to run again                                                            |
| `backend/src/routes/applications.ts`                                        | Eight stages in list order. POST writes the first history row and PUT writes one row when the stage really changes, each in the same transaction as the application write (the row is locked first, so two saves cannot both read the old stage). New `GET /api/applications/:id/status-history` (oldest first, day in Asia/Seoul) |
| `backend/src/openapi.ts`, `docs/openapi.json`                               | The new operation                                                                                                                                                                                                                                                                                                                  |
| `frontend/src/application-data.ts`, `applications.tsx`                      | Stage labels, badge styles (writing, sent, interviewing, offer, rejected, withdrawn), form options, list text                                                                                                                                                                                                                      |
| `frontend/src/application-status-history.tsx`, `cover-letter-questions.tsx` | A "Status history" list on the application page                                                                                                                                                                                                                                                                                    |
| Tests                                                                       | Unit tests (history row on change only, none on a failed save), DB tests (history flow, migration on a scratch schema with every old status), screen tests                                                                                                                                                                         |

DB tests run in CI only (no local PostgreSQL).
