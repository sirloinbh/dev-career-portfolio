# Share selected items as a read-only portfolio page (#236)

Implements the option chosen in #235 (`docs/decisions/0001-portfolio-sharing-access.md`): the app stays behind the sign-in, and one public route serves a revocable token link.

| Area     | Change                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Database | Migration `018_share_links.sql`: label, SHA-256 `token_hash` (unique), chosen ids per kind as `items` jsonb, `created_at`, `revoked_at`. No expiry. The table is listed in `skippedTables`, so the JSON export never carries it                                                                                                                                                                          |
| API      | `GET /api/share/:token` is registered before the sign-in guard (the only such route). It returns only chosen careers, projects, educations and certifications, with explicit public columns (no memos, GPA or scores); 404 for a malformed, unknown or revoked token. `GET/POST /api/share-links` and `POST /api/share-links/:id/revoke` stay behind the sign-in; the token is in the create answer only |
| Web      | `/share` screen (pick items, create, copy the link once, turn a link off) and the public `/share/:token` page, which sits outside the sign-in gate and has no app menu                                                                                                                                                                                                                                   |
| Tests    | Scripted-pool tests for the 404s, the public/private split (every other route and every non-GET share method still 401), validation and hash-only storage; a DB test for chosen-only items and revoke (runs in CI); screen tests                                                                                                                                                                         |

User items: none. Everything not on the share path still needs the sign-in.
